# Data sources and fixtures

All data is synthetic and generated by `uv run p2p generate` (`src/p2p_recon/generate.py`, seed 6042). Same seed, same bytes; a test checks this. No employer data, and supplier and person names are invented.

| Output | Location | In Git |
| --- | --- | --- |
| Policy, the source of every parameter | `reference/p2p_policy.yaml` | Yes |
| Expected outcomes, one row per document or line | `samples/expected_outcomes.csv` | Yes |
| Batch 1: full extracts, batch 2: change log, each with a manifest | `generated/batch_00N/` | No |
| Retrieval documents, with a manifest: policy, local procedures, audit memos, contracts, supplier email and clerk notes. See `src/p2p_recon/corpus.py` | `generated/documents/` | No |
| Embedding model, downloaded on first use | `models/` | No |

## Source shapes

| | SAP-like (GB01) | Oracle-like (DE01) | Group reference |
| --- | --- | --- | --- |
| Files | Semicolon-delimited | Comma-delimited | Comma-delimited |
| Dates | `YYYYMMDD` | `DD-MON-YYYY` | ISO |
| Line numbers | `00010`, `00020` | `1`, `2` | |
| Supplier ids | 10 digits, padded | 4 digits | |
| Credit notes | Positive, `blart = KG` | Negative, `CREDIT` | |
| Three-way flag | `wepos = X` | `match_option = R` | |
| Other | No unit price on invoice lines | `org_id` instead of company code; SUBMIT rows in approval history | Legal entities, items, contracts, policy, FX |

## Contents and defects

60 suppliers, 400 requisitions, their approvals, POs, receipts (including partial deliveries) and invoices, February to September 2026, plus a change log in October. Deliberate defects are the [planted scenarios](../docs/scenarios.md); everything else is clean by construction.

Generated data is ignored by Git through the root `.gitignore`.
